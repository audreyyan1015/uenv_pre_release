# 书生大模型调研

调研范围：本文将“书生大模型”按上海人工智能实验室 Intern 开源体系理解，覆盖文本大模型 InternLM/书生·浦语、科学多模态 Intern-S、通用视觉多模态 InternVL，以及训练、部署、评测、Agent 工具链。

## 1. 与 Qwen3.6-35B-A3B 相仿的书生模型

### 1.1 对标结论

若以 `Qwen/Qwen3.6-35B-A3B` 作为参照，公开书生体系中最接近的候选不是 `InternLM3-8B-Instruct`，而是 Intern-S2 分支：

| 候选模型 | 与 Qwen3.6-35B-A3B 的相似点 | 主要差异 | 建议定位 |
|---|---|---|---|
| `Intern-S2-Preview` / `Intern-S2-Preview-35B` | 35B-A3B 量级；科学多模态模型；支持长上下文、thinking mode、tool calling、MTP 加速；vLLM recipe 标注 36B total / 3B active | 能力重心偏科学任务、科学 workflow Agent 和时间序列；公开材料不是以通用 coding agent 为唯一主目标 | 最适合作为 Qwen3.6-35B-A3B 的同规模书生对标模型，尤其适合 UEnv 的科学任务和环境交互任务 |
| `Intern-S2-Mobius` | 35B/36B 量级；从 Qwen3.5-35B 持续预训练；支持图文输入、OpenAI-compatible serving、vLLM/SGLang/LMDeploy；报告称在保持或提升能力的同时显著提升端到端推理效率 | 重点是“知识-推理解耦”新架构和推理效率；公开对比主要是 Qwen3.5-35B，不是 Qwen3.6-35B-A3B | 更适合作为最新书生 35B 高效率候选跟踪；需要补充 UEnv 本地 coding/agent 实测 |
| `InternLM3-8B-Instruct` | 支持普通对话/深度思考，工具链成熟，部署成本低 | 参数规模和能力上限明显低于 35B-A3B；主要是文本模型 | 可做低成本 smoke 或 ablation，不建议作为能力相仿模型 |
| `Intern-S1-Pro` / `Intern-S2-Preview-397B` | 科学、多模态和 Agent 能力更强 | 1T/397B 级别，资源成本和部署复杂度远超 Qwen3.6-35B-A3B | 可作为上限参考，不适合作为同成本替代 |

因此，本调研建议把 `Intern-S2-Preview` 作为“同规模能力相仿”的主要候选，把 `Intern-S2-Mobius` 作为“同规模高效率新架构”的补充候选。二者都比 InternLM 文本分支更接近 Qwen3.6-35B-A3B 的形态：模型规模接近，具备多模态/Agent 能力，并且可以通过 OpenAI-compatible API 接入 UEnv。

### 1.2 参照对象：Qwen3.6-35B-A3B 的关键能力

Qwen3.6-35B-A3B 是 Qwen3.6 系列首个开源权重模型，官方定位突出 agentic coding、仓库级推理、前端工作流和 thinking preservation。模型卡给出的关键工程参数：

| 维度 | Qwen3.6-35B-A3B |
|---|---|
| 模型类型 | 带视觉编码器的 Causal Language Model |
| 参数规模 | 35B total / 3B activated |
| MoE | 256 experts；每 token 激活 8 routed experts + 1 shared expert |
| 上下文 | 原生 262,144 tokens；可外推到约 1,010,000 tokens |
| 架构特征 | Gated DeltaNet 与 Gated Attention 交替，支持 MTP |
| Agent 能力 | agentic coding、工具调用、长上下文仓库级推理、thinking preservation |
| 官方公开 coding agent 指标 | SWE-bench Verified 73.4，SWE-bench Pro 49.5；脚注说明使用 internal agent scaffold、200K context、temperature=1.0、top_p=0.95 |

对 UEnv 来说，Qwen3.6-35B-A3B 的核心价值不只是“35B 参数”，而是“35B-A3B 稀疏计算 + 长上下文 + 工具调用 + coding agent 后训练”的组合。因此选择书生对标模型时，也应优先看这四类能力是否同时成立。

### 1.3 Intern-S2-Preview：最接近的同规模书生候选

`Intern-S2-Preview` 是当前书生体系中与 Qwen3.6-35B-A3B 形态最接近的公开模型。官方模型卡将其定义为 35B scientific multimodal foundation model，vLLM recipe 进一步标注为 36B total / 3B active、256 experts、hybrid linear/full attention、262K context。它的关键能力包括：

- 科学多模态：面向科学文献、图表、分子、材料、蛋白、时间序列等任务，不只是纯文本问答。
- 长上下文：文本推理评测使用 128K 上限，部署 recipe 标注 base config 为 262K context，并给出 YaRN 外推到 512K 的示例。
- Agent 与工具调用：模型卡提供 OpenAI-compatible tool calling 示例；thinking mode 默认开启，且官方明确不建议在 agentic tasks 中关闭 thinking mode。
- 推理效率：训练和推理侧引入 MTP 与 CoT compression，目标是在保留推理能力的同时降低 response length 和 latency。
- 工程接入：可通过 LMDeploy、vLLM、SGLang 部署；vLLM 路线需要确认 nightly 或对应版本是否支持 `InternS2PreviewForConditionalGeneration`。

与 Qwen3.6-35B-A3B 相比，Intern-S2-Preview 在“规模、激活参数、上下文、工具调用、thinking、MTP、多模态”上高度相似；但能力方向明显不同：Qwen3.6 更偏通用 coding agent 和软件工程任务，Intern-S2-Preview 更偏科学任务、科学 workflow Agent 和科学多模态。因此，如果 UEnv 的任务是 OlymMATH、SciTab、PubMedQA、科学图表/论文页面、时间序列或科学工具链，Intern-S2-Preview 比 InternLM3 更值得作为 Qwen3.6 的对照；如果任务是 SWE-bench Pro / SWE-smith，则仍需要本地实测，不应直接用科学榜单替代 coding agent 指标。

### 1.4 Intern-S2-Mobius：同规模高效率新架构候选

`Intern-S2-Mobius` 是书生体系较新的 35B 候选，适合作为 Qwen3.6-35B-A3B 的效率侧对照。官方模型卡说明它基于 Mobius-v0，由 XTuner 和 LMDeploy 实现，从 Qwen3.5-35B 持续预训练，再经过 SFT 和 RL。Hugging Face 页面标注模型大小约 36B 参数，支持 image-text-to-text，并给出 Transformers、vLLM、SGLang 部署示例。

Mobius 的核心思想是把传统 Transformer 中逐层绑定的 FFN 知识存储与 Self-Attention 推理算子解耦：

- 全局共享 Memory：将知识向量组织为全局共享存储，而不是只绑定在局部层。
- 多个 Reasoner：推理模块可以反复查询共享 Memory，在隐藏状态中做动态迭代。
- Backward Residual Connection：深层和浅层推理阶段可以跨层访问知识，减少只能靠生成长 CoT token 逐步激活知识的依赖。
- Dynamic Latent Reasoning：把一部分审议、修正和多 token 预测内化到连续隐藏状态中，目标是用更短可见推理链完成相同任务。

技术报告中，Intern-S2-Mobius-35B 与 Qwen3.5-35B 对比：通用任务平均分 67.88 vs 65.05，科学任务平均分 52.14 vs 18.20；同时报告称在相近能力下获得接近 4 倍端到端推理加速。这个结果说明 Mobius 更像“同规模、更高推理效率”的路线，而不是单纯堆参数路线。

需要注意：Mobius 公开对比对象主要是 Qwen3.5-35B，而不是 Qwen3.6-35B-A3B；公开材料也没有直接给出 SWE-bench Pro / SWE-smith 与 Qwen3.6 对齐的可复现结果。因此在 UEnv 中使用 Mobius 时，建议先做三类小样本验证：

1. OpenAI-compatible API、chat template、tool call parser 是否与 UEnv Adapter 兼容。
2. thinking/reasoning 输出能否被现有 Worker 和 reward 侧正确解析，是否会出现空 content 或 reasoning/content 分离问题。
3. 在 SWE-smith、DSCodeBench、OlymMATH、SciTab、PubMedQA 各取 20 到 50 条样本，比较任务完成率、平均 response tokens、timeout 率和端到端 latency。

### 1.5 工程选型建议

| UEnv 场景 | 建议模型 | 原因 |
|---|---|---|
| 需要与 Qwen3.6-35B-A3B 做同规模主对照 | `Intern-S2-Preview` | 35B-A3B/36B-A3B、262K context、tool calling、thinking、MTP 这些工程形态最接近 |
| 需要评估 35B 模型的推理效率上限 | `Intern-S2-Mobius` | 重点优化短 CoT 和端到端吞吐，适合做 latency/token 成本对照 |
| 科学任务、多模态科学任务、时间序列任务 | `Intern-S2-Preview`，必要时再看 `Intern-S1-Pro` | S2-Preview 是科学任务主线，资源成本仍在 35B 量级；S1-Pro 只适合作上限参考 |
| 低成本联调、模板验证、接口 smoke | `InternLM3-8B-Instruct` | 部署简单、成本低，但能力不应与 35B-A3B 等同 |
| SWE-bench Pro / SWE-smith 正式对比 | Qwen3.6-35B-A3B + `Intern-S2-Preview` + `Intern-S2-Mobius` 小样本实测 | 公开材料不足以断言书生模型在软件工程任务上等价，需要用同一 UEnv harness 实测 |
