## 4. SSH 恢复后的续跑步骤

### 4.1 检查 worker 状态


如果连不上（`banner exchange` 超时）：等负载自然消退（SWE 容器跑完约需数十分钟），或在阿里云控制台重启该机（机器上只有压测残留，重启安全）。

### 4.2 清理两台 worker 的压测残留

```bash
for h in 8.130.65.20 8.145.51.129; do
  sshpass -p 'dev@BDW2026' ssh -o StrictHostKeyChecking=no root@$h '
    pkill -f "[w]orker_fleet_supervisor"; pkill -x uenv-worker
    pkill -f "[o]penhands_runner"; pkill -f "[l]lm_simulator"; pkill -f "[r]esource_monitor.py"
    sleep 3; pkill -9 -x uenv-worker
    # 先只读确认所有容器确实是 uenv-swe-instance-*；重启后它们会变为 Exited/Dead，
    # 只用 docker ps -q 会漏掉这些残留并导致下一轮 preflight "not container-empty"。
    docker ps -a --no-trunc
    docker ps -aq --filter name=uenv-swe-instance | xargs -r docker rm -f
    echo $HOSTNAME wrk:$(pgrep -xc uenv-worker || echo 0) docker_all:$(docker ps -a -q | wc -l)'
done
```

> **坑**：`pkill -f` 的模式必须加 `[x]` 首字符 trick（如 `"[o]penhands_runner"`），否则模式会匹配到 SSH 会话自己的命令行，把会话杀掉。
>
> **2026-07-28 实测补充**：worker 重启后 .129 留下过 41 个 `Exited/Dead` 的 `uenv-swe-instance-*` 容器；这些容器均为上一轮压测、可安全删除，但先看 `docker ps -a --no-trunc`，不要使用无筛选的 `docker container prune`。
