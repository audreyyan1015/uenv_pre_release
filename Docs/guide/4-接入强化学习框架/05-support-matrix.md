# 支持状态与接入验收

本页是判断强化学习框架能否用于 UEnv 训练的唯一状态页，也是新框架从原型升级为正式支持时的验收清单。

## 如何理解状态

| 状态 | 对用户的含义 | 判定条件 |
|---|---|---|
| **支持** | 可按发布文档运行真实训练 | 有固定版本、公开入口、完整映射和真实端到端验收 |
| **实验** | 只适合研究、联调或复现，不应当作稳定训练入口 | 已有可执行原型，但版本、契约、测试或发布入口尚未齐备 |
| **规划** | 当前不能用它运行 UEnv 训练 | 只有设计、调研或待实现计划 |

有脚本不等于“支持”，有设计文档也不等于“实验”。请以下表的状态和用户入口为准。

## 当前支持状态

| 框架 | 状态 | 用户现在可以做什么 | 当前依据与限制 |
|---|---|---|---|
| VeRL | **支持** | 普通任务使用 `uenv train run-task`；SWE 使用 `uenv train run-swe` | 固定 v0.7.1，已提供 `UEnvAgentLoop`、映射测试和真实训练入口。普通任务目前为单步 Episode，SWE 训练目前只支持 Smith；详见[VeRL 强化学习接入](./04-verl.md) |
| ROLL | **实验** | 可研究或复现 `uenv-bridge/scripts/roll_step_parallel/` 中的实验，不能当作发布训练入口 | 已有实验实现，但还没有固定框架版本、完整公开契约和全部发布验收 |
| NexRL | **规划** | 可阅读架构调研和最小样例规划，当前不能运行 NexRL + UEnv 训练 | 接入 hook、trajectory pool、权重同步和服务边界尚未实现与验收 |

## 新框架的验收门槛

要将一个新框架标记为“支持”，下列五项必须全部通过。实现方法见[自定义强化学习框架接入](./03-custom-framework.md)。

| 验收项 | 必须证明什么 | 应保留的证据 |
|---|---|---|
| 1. 版本与接入点 | 固定框架版本；hook 位于 sample 已选定、rollout 尚未执行的阶段 | 版本声明、hook 路径与最小配置 |
| 2. 双向映射 | 框架 sample 能编码为 `SampleEnvelope`，`SampleResult` 能还原为框架 rollout 输出，且 token、mask、reward 来源明确 | 映射说明和映射单测 |
| 3. 协议与运行语义 | ID 乱序恢复、重复/缺失结果、超时、取消、重试、背压和失败策略都符合 UEnv 契约 | 协议测试结果，以及异步框架的 staleness 测试 |
| 4. 真实闭环 | 适配代码能连接真实 UEnv Server/Worker，并在目标框架中完成至少一次计划内模型更新 | 关联同一 `request_id` 的轨迹/日志、训练指标和可追溯 checkpoint |
| 5. 用户入口 | 新用户有一条可重复的发布命令，并能事先看到已知限制 | 公开运行文档、固定配置和已知限制 |

第 2、3 项的具体字段和运行规则分别以[接口与数据契约](./02-contract.md)和[生产运行语义](./06-runtime-semantics.md)为准。

## 如何更新状态

- 只有设计或调研时，记为“规划”。
- 有可执行原型、但五项验收尚未全部通过时，记为“实验”。
- 五项全部通过后，才能记为“支持”。
- 框架升级导致固定版本、测试或发布入口失效时，应降级状态，而不是继续保留“支持”。

状态变更时，在本页同时更新固定版本、用户入口、已知限制和验收证据；不要只修改宣传性文字。
