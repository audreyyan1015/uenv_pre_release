# 强化学习框架接入指南

本组文档面向开发或维护强化学习框架接入的读者；普通训练用户直接使用[强化学习训练指南](../3-运行任务/07-post-training.md)中的封装入口。

## 组件关系

| 组件 | 归属 | 边界 |
|---|---|---|
| 强化学习框架 | GPU/训练侧 | 采样策略、loss、参数更新与 checkpoint |
| 框架接入代码 | 框架侧的适配代码 | sample ↔ 标准数据包、结果 ID 对齐、token/mask/reward 回填 |
| UEnv Server | 独立中心服务 | UEnv Worker 注册、状态、调度、Episode 生命周期与集中轨迹 |
| UEnv Worker | 环境执行侧 | 模型调用、环境交互、reward 与本地轨迹 |

## 接入顺序

1. 在[支持矩阵](./05-support-matrix.md)确认目标框架当前能否作为发布入口。
2. 阅读[强化学习接入契约](./02-contract.md)，固定 ID、批次、token、失败和并发语义。
3. 已支持的框架按[VeRL 接入](./04-verl.md)使用现有实现。
4. 其他强化学习框架按[自定义强化学习框架接入](./03-custom-framework.md)实现接入代码，并完成四层验收。

ROLL 的仓库脚本只用于实验验证，NexRL 当前只有设计材料；二者都不能因为“仓库里有代码或文档”就写成已支持。

## 接入完成的标准

一个强化学习框架只有在下列条件全部成立时才称为“支持”：

1. 框架 sample 能无歧义映射为 UEnv Server 的标准数据包。
2. 接入代码按 `request_id` 处理乱序、重复、缺失和未知结果。
3. response token、mask、reward、trajectory 和终止原因正确回填。
4. 超时、取消、重试、幂等、背压和失败策略有明确行为。
5. 映射单测、协议测试、本地 UEnv Server/Worker 闭环和真实训练更新全部通过。
6. 发布入口、固定版本、已知限制与验收证据同步写入支持矩阵。

正式支持以上述六条全部满足为准；研究文档、实验脚本、架构草案或只跑通 RPC 都只属于中间状态。
