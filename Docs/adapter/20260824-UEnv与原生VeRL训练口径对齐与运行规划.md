# UEnv 与原生 VeRL 训练口径对齐与运行规划

## 1. 目标

先把原生 VeRL 和 UEnv+VeRL 的训练口径固定到同一套数据、同一顺序、同一 seed、同一 batch 和同一 rollout 配置，再做后续对比。

## 2. 统一口径

- 使用同一份 `train.parquet` / `test.parquet`
- 使用同一批样本和同一读取顺序
- 使用同一组 seed
- 使用同一批大小
- 使用同一 rollout 配置

建议固定为：

- `data.shuffle=false`
- `data.seed=42`
- `actor_rollout_ref.actor.shuffle=false`
- `actor_rollout_ref.actor.data_loader_seed=42`
- `critic.shuffle=false`
- `critic.data_loader_seed=42`
- `actor_rollout_ref.rollout.engine_kwargs.vllm.seed=42`

## 3. 运行规划

1. 先生成一份共享的 SWE-smith VeRL 数据产物，后续两边都复用这份 `train.parquet`。
2. 原生 VeRL 先跑同一份数据和同一套 batch / rollout 参数，作为 baseline。
3. UEnv 再跑同一份数据和同一套 batch / rollout 参数，只切换环境编排路径。
4. 先不实际启动训练，只保留这套对齐口径，等后续需要时直接复用。

正式对比时，数据准备只做一次；两边训练都应关闭重新生成数据，避免 `train.parquet` 在两次运行之间发生变化。

## 4. 对比重点

- step 耗时
- rollout 耗时
- 训练吞吐
- reward / resolved 变化
- 任务执行失败率
