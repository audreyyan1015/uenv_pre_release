## 1. 核心结论（先读）

| 问题 | 答案 |
|---|---|
| Qwen 官方是否公开了 **OpenHands + SWE-bench Pro** 的完整参数？ | **否**。官方 Model Card 的 SWE-bench Pro **49.5%** 使用的是 **Internal agent scaffold（bash + file-edit tools）**，不是 OpenHands。 |

## 3. 参数对比总表

### 3.1 推理与采样

| 参数 | Qwen 官方（Model Card 脚注） | Qwen 官方推荐（Thinking 通用） | OpenHands Index 惯例 / SWE-bench 论文 | Nebius OpenHands 轨迹（Qwen 系） | UEnv 当前 |
|---|---|---|---|---|---|
| **temperature** | **1.0** | 1.0（通用 thinking）/ 0.6（精确 coding） | **0.0**（SWE-bench Live 等 OpenHands 论文） | 0.7 | **0.0** |
| **top_p** | **0.95** | 0.95 | **1.0** | 0.8 | **1.0** |
| **top_k** | 20（社区复现一致采用） | 20 | 未固定 / null | 20 | 未显式设置 |
| **presence_penalty** | 1.5（thinking 通用） | 1.5 | — | — | 未设置 |
| **max_tokens / 每轮输出** | **未设上限**（run-to-completion） | — | null（OpenHands leaderboard 元数据） | 未在 config 限制 | **8192** |
| **thinking / reasoning** | 默认 thinking；支持 `preserve_thinking` | `enable_thinking` + `preserve_thinking` | 视模型而定 | 未在公开 config 写明 | **thinking_budget=4096**，gateway `strip_reasoning` |
| **pass@k / 采样次数** | pass@1 @ temp 1.0 | — | 单次 rollout | 单次 | 单次 |

### 4.6 SWE-bench 论文 / OpenHands 评测惯例

来源：[SWE-bench Goes Live (arXiv)](https://arxiv.org/html/2505.23419v2)

> For OpenHands, we set a maximum of **60 iterations** per instance, with the LLM configured to use a **temperature of 0.0** and a **top-p value of 1.0** as default.

OpenHands 仓库 Issue [#8466](https://github.com/All-Hands-AI/OpenHands/issues/8466) 将 SWE-bench eval 默认 `max_iterations` 统一为 **100**；高端模型 leaderboard 提交可见 **500** iterations。

### 4.7 Qwen 团队对社区 OpenHands 复现的回应

来源：[QwenLM/Qwen3.6#110](https://github.com/QwenLM/Qwen3.6/issues/110)

> You can try to increase the number of turns and the max response length, e.g., **300 turns with 32k tokens for each turn**.

社区反馈：在 OpenHands 上增大 output tokens 与 turns 后，Qwen3.5-35B-A3B 在 Verified 仍 **未超过 63%**（官方 internal 70%）。

### 4.8 社区 SWE-bench Pro 复现关键发现（#179）

| 变量 | bash-only | + str_replace_editor |
|---|---:|---:|
| Qwen3.6-27B reliable@T600 pass@1 | ~27–37% | **~48.9–50.7%** |
| 上下文从 32K→100K 提升 | ~3× | 在 ~100K 后饱和 |

结论：**file-edit 工具类型** 与 **reliable-test 子集** 对能否接近 Model Card 数字的影响，大于单纯调 temperature。

## 6. 差异影响评估（按优先级）

| 优先级 | 差异项 | 可能影响 | 建议方向 |
|:---:|---|---|---|
| **P0** | 上下文 **65K** vs 官方 **200K** | 长轨迹直接 `ContextWindowExceeded`（已观测 23/68 failed） | 提升 vLLM `max_model_len` 至 **128K–200K**（8×A100 需实测 OOM） |
| **P0** | Agent scaffold：OpenHands vs Internal **str_replace** | 社区证据：bash-only 与官方差距 **~20+ pp** | 确认 OpenHands `str_replace_editor` 已启用；长期可对齐 mini-swe+str_replace 作对照实验 |
| **P1** | `max_iterations` **50** vs 社区 **100–300** | 复杂 Pro 任务可能未完成即截断 | 先提到 **100**，稳定后再试 **300** |
| **P1** | `max_tokens` **8192** vs 官方「不限」/ #110 建议 **32K** | 单轮 reasoning 被截断，叠加 thinking budget 更易触顶 | 在更大 ctx 下试 **16K–32K**，或降低 thinking budget |
| **P2** | `temperature` **0.0** vs 官方 **1.0** | Pro 官方为 pass@1 @ temp 1.0；0.0 非官方口径 | 若对齐官方数字，需改为 **1.0** 并多次采样或接受方差 |
| **P2** | 数据集：public 731 vs refined subset | 官方 49.5% 含任务修正；社区 de-flake 影响 ~数 pp | 关注 Qwen 是否公开 refined list |
| **P3** | `strip_reasoning` | 可能损失 `preserve_thinking` 带来的跨轮推理 | 对照实验：`preserve_thinking=true` + 更大 ctx |

## 7. 推荐对齐路线（仅供内部排期）

### 路线 A：对齐 OpenHands 生态惯例（与 Index / 论文一致）

- temperature=0.0, top_p=1.0
- max_iterations=100
- enable_history_truncation=false
- str_replace_editor 开启
- ctx ≥ 131072（如硬件允许）

### 路线 B：对齐 Qwen Model Card 数字（非 OpenHands，仅供参考）

- Internal scaffold + str_replace file-edit
- temperature=1.0, top_p=0.95, top_k=20
- 200K ctx，每轮 max_tokens 不设硬顶
- refined benchmark subset + pass@1

### 路线 C：UEnv 短期可落地（在现有 OpenHands 链路上）

1. vLLM `max_model_len` → **131072**（或 98304 折中）
2. `MAX_TOKENS` → **16384**，`THINKING_TOKEN_BUDGET` → **8192**（或按 ctx 比例调整）
3. `MAX_ITERATIONS` → **100**
4. 保持 temperature=0.0（与 OpenHands SWE 论文一致，便于和 Index 对比）
5. 修复已完成的 prompt / catalog / observability 继续保留
