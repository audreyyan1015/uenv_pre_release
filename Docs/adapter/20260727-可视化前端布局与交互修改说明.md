# 可视化前端布局与交互修改说明

> 日期：2026-07-27
> 面向对象：Adapter / Server Obs / 前端观测面维护者
> 关联范围：`frontend/src/components/training-console.tsx`、`frontend/src/components/ui/resizable.tsx`

## 1. 背景

在前端观测页面中，工作流视图下方曾出现明显空白，且页面需要依赖浏览器整体上下或左右滚动才能看完整内容。工作流视图右上角的定位、居中、全屏、缩放按钮也只是占位按钮，没有绑定实际交互。

本次修改目标是让观测面更接近真实运维控制台：页面固定在一屏内，主要区域支持拖拽调整，工作流画布支持缩放、定位和全屏查看。

## 2. 修改内容

### 2.1 一屏内布局

根容器从 `min-h-screen` 调整为 `h-screen overflow-hidden`，避免浏览器页面本身出现大范围滚动。内容较多时，滚动收敛到对应面板内部，例如工作流画布、对象树、详情面板和事件流表格。

### 2.2 可拖拽面板

使用项目已有的 `react-resizable-panels` / `ui/resizable` 组件替换原先固定 `grid/flex` 布局，新增三组可拖拽分隔条：

| 分隔位置 | 作用 |
|----------|------|
| 工作区与底部事件流之间 | 调整事件流面板高度 |
| 工作流视图与右侧信息区之间 | 调整 workflow 与对象详情区域宽度 |
| 对象层级树与节点详情之间 | 调整右侧上下两个面板高度 |

这样可以在展示较长事件流时放大底部区域，也可以在只关注 workflow 时将事件流压缩。

### 2.3 工作流画布交互

工作流视图右上角工具按钮已从占位改为真实交互：

| 按钮 | 当前行为 |
|------|----------|
| 定位 / 居中当前节点 | 将当前选中的 workflow 节点滚动到画布中央 |
| 全屏 | 调用浏览器 Fullscreen API，进入或退出工作流视图全屏 |
| 缩小 / 放大 | 调整工作流画布缩放比例，范围为 60% 到 160% |
| 百分比文本 | 显示当前缩放比例，点击可重置为 100% |

### 2.4 依赖版本适配

当前仓库安装的 `react-resizable-panels` 为 `4.11.2`，其面板组方向字段为 `orientation`。因此同步修正了 `ui/resizable.tsx` 中依赖的 data attribute，从旧的 `data-panel-group-direction` 改为 `data-panel-group-orientation`，保证垂直分隔条样式和把手旋转方向正确。

### 2.5 工作流关联实体计数口径

工作流卡片中的“关联实体”数字由前端直接读取 Server Obs 返回的 `workflow.nodes[].payload_summary.count`：

```text
stage.payload_summary.count
```

如果 Server Obs 没有填充该字段，前端会按 `0` 展示。因此真实页面中出现 `SUBMIT / DISPATCH / EXECUTE / REPORT / DONE` 全部为 `0 关联实体`，并不一定表示真实链路没有 Episode，而是说明当前 Obs state 中 workflow 节点缺少统计摘要。

当前已观察到的真实 state 现象：

```text
submit DONE payload_summary=None
dispatch DONE payload_summary=None
execute DONE payload_summary=None
report DONE payload_summary=None
done DONE payload_summary=None
```

建议后续在 Server Obs projection / merge 层维护 `payload_summary.count`，而不是只在前端兜底推断。推荐口径如下：

| workflow 节点 | `payload_summary.count` 建议含义 |
|---------------|----------------------------------|
| `submit` | 已提交 Episode 数 |
| `dispatch` | 已调度 Episode 数 |
| `execute` | 已进入执行或 step 阶段的 Episode 数 |
| `report` | 已完成或失败并回传结果的 Episode 数 |
| `done` | 已到终态的 Episode 数 |

前端可以保留缺省显示 `0`，但权威计数应由 Server Obs 输出，避免不同观测消费端各自推断造成口径不一致。

## 3. 查看方式

仅查看 UI 布局时可以使用 fixture 演示模式，不依赖真实 Server Obs 数据：

```bash
cd /data/ronghao/uenv/frontend
PATH=/data/ronghao/.local/node-v22.12.0-linux-x64/bin:$PATH \
npm run dev -- --host 0.0.0.0 --port 8080
```

浏览器访问：

```text
http://10.10.20.142:8080/
```

如果需要接真实 Obs 数据，应在启动前配置 `VITE_AGGREGATION_BASE_URL` 和 `VITE_DEFAULT_RUN_ID`，并访问带 `run` 参数的页面：

```bash
cd /data/ronghao/uenv/frontend
VITE_AGGREGATION_BASE_URL=http://<server-obs-host>:50053 \
VITE_DEFAULT_RUN_ID=<training_run_id> \
PATH=/data/ronghao/.local/node-v22.12.0-linux-x64/bin:$PATH \
npm run dev -- --host 0.0.0.0 --port 8080
```

```text
http://10.10.20.142:8080/?run=<training_run_id>
```
