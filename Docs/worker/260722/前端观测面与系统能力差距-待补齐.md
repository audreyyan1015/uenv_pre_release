## 3. 前端界面能力 vs 系统实际支持（对照表）

### 3.1 观测（Obs / ChainState）

| UI 能力 | 前端现状 | 系统 / Obs 现状 | 差距 |
|---------|----------|-----------------|------|
| 工作流图（SUBMIT→…） | 已绑 `ChainState.workflow` | Server 控制面 `try_emit` 投影 episode 生命周期；seed 可造假数据 | **缺真实联调证据**；CodeAgent/ToolEnv 路径观测粒度是否与 SWE/native 一致待核 |
| 对象树（run→worker→episode→step） | 已绑 `tree` | merge/project 支持 worker/episode；step 主要靠 StreamReport 转译 | Step 细粒度在 Agent 路径可能偏少 |
| SSE 直播 + 连接态 | `useRunStream`；失败回落 fixture | `GET .../stream` 推 `full_state` / `state_delta` / `run_status` / `ping` | `Last-Event-ID` 服务端未做增量重放（重连靠 full_state，P0 可接受） |
| 本地快照 live↔snapshot | FE-3 本地深拷贝已有 | 不依赖后端 | 无 IndexedDB 持久化（可选） |
| 事件流 Tab | 由当前 `ChainState` **派生**近期变化 | 无独立「原始事件查询」API | 不是服务端事件日志；运维排查仍靠 Server 日志 |
| Fixture / Mock 回落 | 未配 URL 或 Obs 失败时演示 | — | 联调时易误判为「链路在动」；须看顶栏是否「Fixture / Mock 回落」 |
| Run 列表 / 切换 | 仅 URL `?run=` / `VITE_DEFAULT_RUN_ID` | `GET /api/v1/runs` 已有 | **前端未接 run 列表 UI** |
| Obs 公网直连 | 经 `:8888/obs` 代理 | `:50053` 仅本机 listen | 生产需反代或安全组策略；Bridge 机访问 Obs 需隧道/同机 |

### 3.2 控制（训练启停）

| UI 能力 | 前端现状 | 系统现状 | 差距 |

### 3.4 Bridge 上报面（真实联调关键）

| 能力 | 现状 | 差距 |
|------|------|------|
| `UENV_OBS_URL` + `obs_client` | Bridge 可发 `RUN_STARTED` / `RUN_STOPPED` / `RUN_CLOSED`；失败不打断训练 | **实机联调未配通并验收** |

## 5. 建议补齐项（按优先级）

### P0 — Bridge：真实观测联调（不改产品边界）

1. 配置 `UENV_OBS_URL`，固定 `training_run_id`，打开 `http://8.130.75.157:8888/?run=<id>`。  
2. 跑 ≥1 条真实 `qa` 或已验证 B3 `code` Episode。  
3. 验收工作流变色、树增长、`RUN_*` 与顶栏一致。  
4. 记录：run id、episode id、截图/日志关键字 → 回写综合报告。

### P1 — Server / FE：观测增强

| ID | 项 | 建议 |
|----|----|------|
| G-1 | Run 列表 UI | 接 `GET /api/v1/runs`，避免只靠手改 URL |
| G-2 | CodeAgent / 分池观测 | Obs 或 admin 暴露 pool/bridge；前端树或详情可区分 SWE vs ToolEnv |
| G-3 | 日志 Tab | 定义只读 API（或深链 trajectory/admin），按 run/correlation 拉 |
| G-4 | Metrics Tab | 最小：活跃 episode、worker 数、dropped_events；进阶：分池吞吐 |
| G-5 | SSE cursor 重放 | 消费 `Last-Event-ID`，减少重连全量 |

### P1 / P2 — 控制面（若产品确认「页面可开战」）

| ID | 项 | 建议 |
|----|----|------|
| C-1 | `POST /api/v1/runs` | 明确创建的是「观测 run」还是触发 Bridge/VeRL job；避免假开战 |
| C-2 | `POST .../stop` | 与 CancelEpisode / 关 batch 语义对齐 |
| C-3 | 前端解禁按钮 | 仅在 C-1/C-2 就绪后；否则保持只读 |

> **默认建议**：短期维持 **观测与控制分离**——训练仍由 Bridge/脚本发起，前端只读；先完成 P0 真实联调再开控制 API。

## 6. 联调时易混淆点（防误判）

| 现象 | 常见原因 |
|------|----------|
| 工作流在动，但不是本次作业 | Fixture / Mock 回落，或盯着 `_orphan` seed |
| 真实 Episode 成功，UI 空 | `?run=` 与 Bridge `training_run_id` 不一致 |
| Bridge 无 Obs 日志 | 未设 `UENV_OBS_URL`，或 50053 从发起机不可达 |
| Server 启动卡住 / 无 8088 | `obs.db` 过大重放阻塞（曾轮转 `obs.db.bak-heavy-*`） |

---

## 7. 验收定义（写回综合报告用）

**「前端真实联调完成」** 仅当同时满足：

1. 顶栏 **非** Fixture/Mock，且 `training_run_id` = 本次 Bridge/作业 id；  
2. 至少一条真实 Episode 使工作流节点与树更新；  
3. `RUN_STARTED`→业务事件→`RUN_CLOSED`（或等价终态）在 UI 与 `GET .../state` 一致。

**不纳入该验收**：开始/终止按钮、日志/Metrics 实数、历史回放（记入本文 §5 P1+）。
