# 前端服务器同步与无侵入联调推进规划

> **日期**：2026-08-13
> **依据**：[`secrets/README.md`](../../../secrets/README.md)、[Worker前端同步与联调记录](../260805/Worker前端同步与联调记录.md)、[Worker与环境资源池前端改造实施规划](./Worker与环境资源池前端改造实施规划.md)
> **目标**：将本地完成的前端改造同步到实际 Server 侧前端运行目录，完成真实舰队数据联调，同时避免重启或修改正在承载训练测试的 Core/Server、Worker 和 Agent 进程。

## 1. 当前实际部署判断

### 1.1 前端部署形态

既有联调记录明确：

```text
主机：8.130.75.157
目录：/home/uenv-frontend-add/frontend
服务：vite dev --port 8888 --host 0.0.0.0
访问：http://8.130.75.157:8888/
```

前端是独立的开发服务器，不是 `uenv-adapter-core` 的同一进程。既有记录还明确上次同步时只重启了 `:8888` 前端进程，`uenv-adapter-core` PID 全程保持不变。

### 1.2 Server/Adapter 实际边界

`8.130.75.157:8088` 不是纯 Adapter 进程，而是同一个 `uenv-adapter-core` 进程同时承载 Adapter、ControlPlane、AgentControl 和 Admin 服务。该进程由 `uenv-server` 或 `uenv-adapter-core` 的 systemd 单元管理，不能为了更新前端而重启。

### 1.3 Worker 和 Agent 边界

```text
7143       uenv-worker，独立于前端
8.130.208.77  Agent/OpenHands，独立于前端
8.130.75.157  uenv-adapter-core + Server，独立于前端
8.130.75.157  前端 Vite 服务 :8888，独立于上述执行进程
```

### 1.4 前端读取链路

当前 Vite 开发代理默认使用：

```text
/obs/*   → http://127.0.0.1:50053
/fleet/* → http://127.0.0.1:50052
/hub/*   → http://127.0.0.1:8088
```

因此前端部署在 Server 主机上时，可通过本机回环访问 Server 的 Obs 和 Admin 只读接口；本轮环境资源池页面使用 `/fleet/workers`，不会新增控制面请求。

## 2. 安全结论

### 2.1 可以无侵入同步的条件

满足以下条件时，前端同步不会影响正在运行的训练测试：

- 只修改 `/home/uenv-frontend-add/frontend` 或其备份目录；
- 只重新构建或重启 `:8888` 前端进程；
- 不执行 `systemctl restart uenv-server`；
- 不执行 `systemctl restart uenv-adapter-core`；
- 不执行 Worker 重启脚本；
- 不执行 Agent poller、OpenHands runner 或 Gateway 重启；
- 不使用 `pkill`、`killall` 或按模糊名称杀进程。

### 2.2 明确禁止

以下操作不属于前端同步，可能影响正在进行的 Episode 或训练：

```text
systemctl restart uenv-server
systemctl restart uenv-adapter-core
systemctl restart uenv-worker
systemctl restart uenv-agent-poller
restart-worker-gateway-28097-7143.sh
pkill uenv-adapter-core
```

尤其不能把前端发布与 `uenv-adapter-core` 二进制更新合并执行。`:8088` 上 Adapter 和 Server 共用同一进程，重启它会造成控制面短暂中断，影响风险取决于当前任务和服务的恢复状态。

### 2.3 凭据要求

本规划不复制、打印或写入任何 SSH 私钥、密码、Hub Token、LLM Key 或前端客户端 Token。具体凭据只从本地受保护的 `secrets/`、SSH agent 或服务器既有权限配置中读取。

## 5. D1：远端只读快照

在同步前，只采集状态，不修改服务：

```bash
systemctl is-active uenv-server.service uenv-adapter-core.service uenv-worker.service
ss -ltnp | grep -E ':8888|:8088|:50052|:50053|:8077|:28888|:28097'
ps -ef | grep -E 'vite|uenv-adapter-core|uenv-worker|openhands|agent' | grep -v grep
curl -fsS http://127.0.0.1:50052/status
curl -fsS http://127.0.0.1:50053/health
curl -fsS http://127.0.0.1:8888/server/worker?worker=worker-7143-pro
```

实际路径和接口应以远端当前进程为准；如果 `:8888` 不是 Vite 进程或路径发生变化，应暂停 D2，先确认发布方式。

记录训练保护快照：

- 当前训练 Run ID；
- Server 进程 PID；
- Worker 进程 PID；
- Agent 进程 PID；
- 当前 Worker 数量、负载、容量和活跃 Episode 数；
- 同步前页面可访问性。

验收要求：同步前后 Core/Server、Worker、Agent 的 PID 不应因为前端发布发生变化。

## 6. D2：远端备份和同步

### 6.1 备份

在远端创建带时间戳的前端备份：

```text
/home/uenv-frontend-add/backups/<timestamp>/
```

至少备份：

- `src/`；
- `package.json` 和 lock 文件；
- `vite.config.ts`；
- 当前 `.env*` 配置（不要回传或提交）；
- 当前运行方式和进程命令记录。

### 6.2 同步策略

优先同步前端源代码和 lock 文件，在远端目录执行远端构建。这样可以避免将 macOS 生成的依赖或平台相关产物直接复制到 Linux。

同步范围只包括：

```text
frontend/src/
frontend/package.json
frontend/package-lock.json 或 frontend/pnpm-lock.yaml（以实际存在者为准）
frontend/vite.config.ts
frontend/tsconfig*.json
```

不要同步：

```text
node_modules/
dist/
本地 .env 中的秘密配置
```

### 6.3 远端构建

在远端前端目录执行：

```bash
npm run lint
npm run build
```

如果远端当前使用的是 `pnpm`，遵循远端现有 lock 文件和既有命令，不混用包管理器。

## 7. D3：仅切换前端服务

当前既有记录显示前端使用 Vite dev。切换前先确认其 PID 和父服务关系：

```bash
ps -o pid,ppid,command -p <frontend_pid>
```

只停止/启动该前端进程；不按通配名称杀进程，不触碰 `uenv-adapter-core`、Worker 或 Agent。

如果实际采用生产 SSR：

- 只重启独立的前端 systemd service；
- 不重启 `uenv-server.service` 或 `uenv-adapter-core.service`；
- 优先使用新目录启动，再切换反向代理或端口，减少前端不可用时间。

预期影响：浏览器访问 `:8888` 可能短暂中断或触发 HMR/页面刷新；训练控制面和已有测试进程不应中断。

## 8. D4：真实数据联调

按以下顺序验收：

1. `/server?run=<current_run>`：确认 Episode 进度和执行节点列表仍正常。
2. `/server/worker?run=<current_run>&worker=<worker_id>`：确认单执行节点详情、心跳、活跃 Episode 和本地运行时池正常。
3. `/server/pools`：确认跨节点环境资源池聚合、环境类型、ready/busy/warming、容量和执行节点下钻正常。
4. `/system?run=<current_run>`：确认拓扑中的“环境资源池”入口可用，资源池卡片指向 `/server/pools`。
5. 检查浏览器 Network：`/fleet/workers` 为只读 GET，未出现控制类请求。

联调记录至少保存：

- 页面 URL；
- 当前 Run ID；
- 环境资源池数量；
- Worker/执行节点数量；
- 每个池的 ready、busy、warming、capacity；
- 下钻链接是否带正确 `worker` 参数。

## 9. D5：训练无影响验收

前端切换前后对比：

| 检查项 | 期望 |
|---|---|
| `uenv-adapter-core` PID | 不变 |
| Server `:8088` | 持续监听 |
| Admin `:50052` | 持续可读 |
| Obs `:50053` | 持续健康 |
| Worker PID | 不变 |
| Worker 心跳 | 连续，无因发布导致的长间隔 |
| 活跃 Episode | 数量和 ID 正常变化，不被清空 |
| Agent PID/状态 | 不变 |
| 训练进程 | 不变 |
| 前端 `:8888` | 新页面和新路由可访问 |

如果任一核心进程 PID 变化、Worker 心跳中断、活跃 Episode 异常消失或训练进程退出，立即停止继续联调并执行回滚。

## 10. 回滚方案

前端回滚只恢复：

```text
/home/uenv-frontend-add/frontend
```

从最近一次备份恢复源代码或生产产物，随后只重启前端服务。禁止用回滚操作触碰 Core/Server、Worker 或 Agent。

回滚后重新验证：

- `:8888` 页面可访问；
- `/server/worker` 旧页面可打开；
- Core/Server、Worker、Agent PID 与回滚前一致；
- 当前训练 Run 仍可查询。

## 11. 当前决策

- **可以继续推进服务器侧联调**，但只同步前端。
- **不需要同步 Server/Worker Rust 代码**，本轮前端页面依赖的 `/fleet/workers` 已存在。
- **不需要重启 `uenv-adapter-core`**；该重启会影响控制面，必须排除在本轮操作之外。
- **第一选择是复用现有 `/home/uenv-frontend-add/frontend` + `:8888` 部署形态**，因为已有无侵入联调记录。
- **第二选择才是部署独立生产 SSR 前端服务**；如采用，需先确认独立 systemd/反向代理单元，不能假设已有部署脚本安全。
- 远端同步前必须先执行 D1 只读快照，确认实际前端 PID 和服务关系。
