# 概念对照表：代码协议字段与对外展示名称

> **日期**：2026-08-13  
> **用途**：供工程开发、接口联调、前端实现和文档查阅使用  
> **核心规则**：代码/协议名称与产品展示名称可以不同；除非有明确迁移计划，不要因为展示名称变化而擅自修改协议字段。

---

## 1. 使用规则

### 1.1 三种名称层次

| 层次 | 用途 | 示例 |
|---|---|---|
| 代码/协议名 | Rust、TypeScript、Protobuf、JSON、日志和兼容接口 | `worker_id` |
| 架构概念名 | 架构设计、模块边界、技术方案 | Execution Node |
| 用户展示名 | 前端标题、卡片、导航、帮助文案 | 执行节点 |

### 1.2 必须遵守

- 看到 `worker` 时，默认理解为“执行节点”的代码/协议标识。
- 看到 `env_instance` 时，默认理解为“隔离环境运行时”的代码/协议标识。
- 看到 `pool_summary` 或 `pool_slots` 时，默认理解为单个 Worker 的本地池数据。
- 只有跨多个 Worker 聚合后的数据才称为“环境资源池”。
- 不把 `worker` 翻译成“服务器”，也不把 `env_instance` 翻译成“容器”。
- 新增字段前先确认是兼容协议字段、内部模型字段，还是用户展示字段。

## 2. 核心概念对照

| 代码/协议名称 | 中文概念名 | 英文概念名 | 用户展示名 | 作用域/说明 |
|---|---|---|---|---|
| `worker` | 执行节点 | Execution Node | 执行节点 | 可被 Server 调度的运行节点，当前通常绑定一台服务器 |
| `worker_id` | 执行节点标识 | Execution Node ID | 执行节点 ID | 稳定标识；协议字段继续使用 `worker_id` |
| `WorkerInfo` | 执行节点信息 | Execution Node Info | 执行节点信息 | Server 调度器内部的节点记录 |
| `WorkerView` | 执行节点视图 | Execution Node View | 执行节点 | Obs/前端状态投影 |
| `WorkerPoolRegistry` | 执行节点资源目录 | Execution Node Resource Registry | 执行节点资源目录 | 当前 Worker Pool 层的资源注册/查询组件 |
| `env_instance` | 隔离环境运行时 | Isolated Environment Runtime | 环境运行时 | 一个独立生命周期和故障边界的环境执行单元 |
| `env_instances` | 隔离环境运行时列表 | Environment Runtime List | 环境运行时 | Worker 视图中的实例 ID 列表，字段暂不改名 |
| `instance_id` | 环境运行时标识 | Environment Runtime ID | 运行时 ID | 单个运行时的标识 |
| `WarmupPool` | Worker 本地环境运行时池 | Worker-local Environment Runtime Pool | 本地环境运行时池 | 单个 Worker 内按环境类型管理的运行时集合 |
| `pool_summary` | 本地池汇总 | Local Pool Summary | 本地池汇总 | 单个 Worker 按环境类型/变体的 ready、busy 等统计 |
| `pool_slots` | 本地运行时槽位 | Local Runtime Slots | 本地运行时槽位 | 单个 Worker 上的槽位明细 |
| `WorkerPoolSummary` | 本地池汇总项 | Local Pool Summary Item | 环境类型池汇总 | Protobuf/JSON 中的 Worker 级池统计项 |
| `WorkerPoolSlot` | 本地运行时槽位 | Local Runtime Slot | 运行时槽位 | Protobuf/JSON 中的 Worker 级槽位项 |
| `warm` / `ready` | 预热/就绪运行时 | Warm / Ready Runtime | 就绪 | 运行时生命周期或池状态，不是独立池类型 |
| `busy` / `active` | 忙碌/活跃运行时 | Busy / Active Runtime | 执行中 | 当前绑定 Episode 或正在执行 |
| `warming` | 预热中运行时 | Warming Runtime | 预热中 | 正在创建或初始化 |
| `failed` / `broken` | 失败/损坏运行时 | Failed / Broken Runtime | 异常 | 不得继续回到可用池的运行时 |
| 新增全局聚合模型 | 全局环境运行时池 | Global Environment Runtime Pool | 环境资源池 | 跨所有执行节点聚合的逻辑资源集合 |
| 新增用户页面 | 环境资源池页面 | Environment Resource Pools | 环境资源池 | 用户查看所有服务器环境能力与容量的页面 |

## 3. 字段级对照

### 3.1 Worker/执行节点字段

| 代码/协议字段 | 展示含义 | 展示建议 |
|---|---|---|
| `worker_id` | 执行节点标识 | “执行节点 ID”或节点名称；不显示为“服务器 ID” |
| `endpoint` | 执行节点接入端点 | “接入端点” |
| `status` | 执行节点运行状态 | “运行状态” |
| `status_reason` | 运行状态原因 | “状态原因” |
| `load` / `current_load` | 当前执行负载 | “当前负载” |
| `capacity` / `max_load` | 最大并发容量 | “容量”或“最大并发” |
| `last_heartbeat_secs` / `last_heartbeat_ts` | 最近心跳信息 | “最近心跳” |
| `episodes` / `active_episodes` | 当前活跃 Episode | “当前执行”或“活跃任务” |
| `supported_env_types` | 支持的环境类型 | “支持的环境类型” |
| `platform_features` | 执行节点平台能力 | “平台能力” |
| `backend_kinds` | 环境运行时 Backend 类型 | “运行时 Backend”或“后端类型” |
| `package_states` | 已同步环境包状态 | “已准备环境包” |

| 代码/协议字段 | 展示含义 | 展示建议 |
|---|---|---|
| `env_instances` | Worker 上的环境运行时 ID 集合 | “环境运行时” |
| `instance_id` | 单个运行时 ID | “运行时 ID” |
| `env_type` | 环境能力类型 | “环境类型” |
| `variant` | 环境变体 | “变体” |
| `package_id` | 环境包标识 | “环境包” |
| `package_version` | 环境包版本 | “环境包版本” |
| `backend_kind` | 运行时承载后端 | “Backend”或“运行时后端” |

| `session_id` | 运行时关联的会话标识 | “会话 ID”，不等同于运行时 ID |

| 代码/协议字段 | 实际范围 | 展示名称 |
|---|---|---|
| `pool_summary` | 单 Worker | 本地池汇总 |
| `pool_slots` | 单 Worker | 本地运行时槽位 |
| `ready` | 单 Worker 或聚合池 | 就绪 |
| `busy` | 单 Worker 或聚合池 | 执行中 |
| `warming` | 单 Worker 或聚合池 | 预热中 |
| `capacity` | 单 Worker 或聚合池 | 容量 |

| `runtime_count` | 聚合池 | 运行时总数 |
| `failed` | 聚合池或本地池 | 异常运行时数 |

## 4. 页面和路由对照

| 当前代码路径/组件 | 当前技术含义 | 固定后的产品名称 | 页面范围 |
|---|---|---|---|
| `/server` | Episode 进度页 | Episode 进度 | 用户任务级 |
| `/server/worker` | 单 Worker 详情 | 执行节点详情 | 单节点机器级 |
| `WorkerDetail` | 单 Worker 详情组件 | Execution Node Details | 单节点机器级 |
| `worker-status-overview` | Worker 舰队列表 | 执行节点舰队 | 多节点列表 |
| 建议新增 `/server/pools` | 跨 Worker 环境池聚合 | 环境资源池 | 用户资源级 |
| `SystemTopology` | 系统拓扑和运行流程 | 系统拓扑 | 系统级导航与状态 |

### 4.1 `/server/worker` 的固定语义

```text
/server/worker
    = 单个 Worker 的机器级详情
    = 单个执行节点的本地运行时和活跃任务详情
```

该页面中的 `pool_summary` 和 `pool_slots` 必须标注或通过文案表达“本地”范围。

### 4.2 `/server/pools` 的固定语义

```text
/server/pools
    = 所有执行节点上的环境运行时聚合
    = 面向用户的环境资源池总览
```

该页面不得把聚合池误展示为某一个 Worker 的实际进程池；它是统计和导航抽象。

## 5. 日志、指标和接口阅读规则

### 5.1 日志字段

日志中的 `worker_id`、`env_type`、`instance_id` 等字段保持技术名称，以便检索和跨服务关联。日志消息中可以补充用户语义，但不替换结构化字段：

```text
worker_id=worker-1 node_role=execution_node
env_type=math instance_id=inst-1 runtime_role=isolated_environment_runtime
```

是否新增别名日志字段需要单独评估，不能在普通改名任务中随意增加。

### 5.2 指标

已有指标中的 `worker`、`instance`、`pool` 标签继续按协议和指标兼容性使用。指标说明文档必须标注作用域，例如：

```text
uenv_instance_pool_size{worker_id,env_type,status}
    = Worker-local Environment Runtime Pool
```

如果新增全局指标，应使用明确的聚合语义，例如：

```text
uenv_global_environment_runtime_count{env_type,status}
```

不要让同一个指标名在不同页面分别表示本地池和全局池。

### 5.3 API

```text
GET /fleet/workers
    → Execution Node snapshots
    → pool_summary/pool_slots are worker-local

GET /fleet/environment-pools
    → Global Environment Resource Pool aggregation
```

## 6. 常见误用和纠正

| 不推荐说法 | 推荐说法 | 原因 |
|---|---|---|
| Worker 服务器 | Worker 执行节点 | Worker 不是 Host 的同义词 |
| Worker Server | 执行节点服务 / Worker 服务 | 避免与 `uenv-server` 混淆 |
| 容器实例 | 隔离环境运行时 | ProcessBackend 下未必是容器 |
| 全局 WarmupPool | 环境资源池 | `WarmupPool` 当前是 Worker 本地池 |
| Worker Pool 总池 | Worker 本地环境运行时池 | 明确作用域 |
| env instance session | 环境运行时与会话 | `session_id` 不等于运行时 ID |
| pool 统计 | 本地池统计 / 全局池统计 | 必须说明范围 |

## 7. 最短查阅版

```text
worker
  = code/protocol name
  = Execution Node / 执行节点

env_instance
  = code/protocol name
  = Isolated Environment Runtime / 隔离环境运行时

WarmupPool
  = current worker-local pool implementation
  = Worker-local Environment Runtime Pool / Worker 本地环境运行时池

pool_summary / pool_slots
  = worker-local data
  = 本地池汇总 / 本地运行时槽位

Environment Resource Pool
  = new cross-worker user-facing aggregation
  = 环境资源池
```
